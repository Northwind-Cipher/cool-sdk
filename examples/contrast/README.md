# CooL × Contrast — a confidential AI service with verifiable change history

An AI service that runs inside an [Edgeless Systems Contrast](https://docs.edgeless.systems/contrast)
confidential workload and seals independently verifiable evidence of everything that changes
about it: the model, the system prompt, the agent's permissions, the parameters.

```
Contrast  →  this pod ran as a confidential container, on hardware matching a signed manifest
CooL      →  this is what changed inside it, it has not been altered, and here is the proof
             that it came from THAT pod
```

## Try it with no cluster, in ninety seconds

```sh
npm install                       # in the repository root
npm run demo:contrast
```

Seven acts: the workload's Contrast identity, four AI changes sealed inside it, an independent
verdict, then four forgeries that must fail — a stolen credential, a full double swap, a
Coordinator nobody attested, and a rebuilt image.

It runs against `tests/fixtures/contrast-fixtures.json`, generated by **Contrast's own code**
(see [`tools/contrast-fixture/`](../../tools/contrast-fixture)). Every certificate chain,
extension and signature is real. The hardware is not: the TDX quote behind those certificates was
built in software. The demo says so.

## Run the service locally

```sh
# pod.mjs writes one fixture workload out as the files Contrast's initializer
# creates, into a temp directory, and prints the path.
COOL_CONTRAST_ROOT=$(node --import tsx pod.mjs ai-service) node ai-service.mjs
```

```sh
curl -s localhost:8080/identity | jq .contrast
curl -s -XPOST localhost:8080/infer  -d '{"prompt":"refund $620 for order 19"}'
curl -s -XPOST localhost:8080/change -d '{"kind":"prompt","ref":"billing/refund-agent#system","after":"Escalate above $200."}'
curl -s localhost:8080/receipts > receipts.json
```

## Deploy it for real

Needs a Kubernetes cluster with bare-metal Intel TDX or AMD SEV-SNP (or AKS CoCo), the Contrast
node-installer and runtime class applied, and the `contrast` CLI. Follow Edgeless's
[workload deployment guide](https://docs.edgeless.systems/contrast/howto/workload-deployment/runtime-deployment)
for the cluster prerequisites first.

```sh
./deploy.sh metal-qemu-tdx        # or metal-qemu-snp, aks-clh-snp, …
```

Read `deploy.sh` before running it — it is deliberately just the five `contrast` commands in
order, plus one step that publishes `manifest.json` to the pod so CooL can seal its digest.

**These manifests have not been applied to a real cluster.** They are written against Contrast's
current generator and are unvalidated. See [`docs/contrast.md`](../../docs/contrast.md) §7.

## Verify, as an auditor

The whole point: no cluster access, no network, no trust in whoever ran the workload.

```sh
node verify.mjs receipts.json \
  --coordinator-root verify/coordinator-root-ca.pem \
  --manifest manifest.json \
  --require-hardware
```

The Coordinator root must come from **your own** `contrast verify -c <coordinator>`, which
remotely attests the Coordinator CVM against the manifest's reference values. A root taken from
the pod would make the chain circular — and without any pinned root the `workload` domain reports
rather than passes, so `--require-hardware` will fail. That friction is the feature.

## What is in here

| file | what it is |
| --- | --- |
| `ai-service.mjs` | the workload. The integration is the first six lines of the file. |
| `verify.mjs` | the auditor's side: receipts + two files in, verdicts out |
| `demo.mjs` | the end-to-end demo, fixtures only, no cluster |
| `pod.mjs` | materialises one fixture workload on disk, for running the service locally |
| `k8s/ai-service.yaml` | a normal Deployment plus the three lines Contrast needs |
| `Dockerfile` | reproducible image, no baked signing key (there is nothing to bake) |
| `deploy.sh` | coordinator → generate → manifest → set → apply → verify |

## The three lines that adopt it

```yaml
runtimeClassName: contrast-cc                                   # marks the pod for Contrast
metadata.annotations:
  contrast.edgeless.systems/workload-secret-id: default/ai-service   # releases the sealed secret
env:
  - name: COOL_CONTRAST_ROOT
    value: /contrast                                            # tells CooL to use it
```

Without the annotation the Coordinator releases no workload secret, and CooL refuses to start
with exactly that message and the fix.
